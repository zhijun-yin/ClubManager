# 验证记录

验证日期：2026-10-22（Asia/Shanghai）。

## 最终环境与结果

主环境为 WSL `Ubuntu-24.04`（Ubuntu 24.04.4），GCC 13.3、CMake 3.28、Python 3。OpenSSL 来自 Ubuntu `3.0.13-0ubuntu3.16` 包，解包于项目私有目录。Windows 智能应用控制保持开启；最终原生 Windows EXE 被策略拦截，不能视为运行通过。

在项目中文路径下执行：

```powershell
.\run-wsl.ps1 -Action test
```

实际 CMake/CTest 输出：

```text
ALL TESTS PASSED (641 checks)
HTTP/CLI TESTS PASSED (55 checks)
AUTHORIZATION TESTS PASSED (197 checks)
100% tests passed, 0 tests failed out of 3
Total Test time (real) = 15.32 sec
```

合计 893 项检查通过。最终构建启用 `-Wall -Wextra -Wpedantic`，无编译警告；内嵌 JavaScript 提取后经 `node --check` 验证语法。Linux 构建目录由 `build/wsl-build-path.txt` 指向，完整测试日志在该目录的 `Testing/Temporary/LastTest.log`。

## 浏览器检查

本地 `http://127.0.0.1:8091/` 使用 `build/preview/` 的独立虚构样例，当前服务由 WSL 程序提供。

1. 登录界面正常；普通成员登录后显示本人绑定身份，成员选择控件禁用，导航只有本人可用功能。
2. 成员取消报名、重新报名并签到成功；已签到后签到/取消控件禁用，积分只增加一次。
3. 成员提交前端组入社申请，在“我的申请”看到待审记录，撤回后显示“已撤回”且不能重复撤回。
4. 退出后以管理员登录，显示管理导航；账号页展示账号角色、成员绑定、启停及密码重置入口。
5. 更早的业务交互检查覆盖总览、日程、积分撤销、姓名/标签搜索、活动名单与 CSV 下载。最终登录版的截图已更新。

浏览器未提交新密码或重置密码表单；这些流程由真实 HTTP/CLI 权限测试覆盖。截图：[登录](login.png)、[成员](member-login.png)、[账号管理](admin-accounts.png)、[总览](dashboard.png)、[活动](activities.png)。CLI 示例见 [terminal_output.md](terminal_output.md)。

## 双击启动入口补充验证

运行 `python3 tests/test_launcher.py`，在临时数据目录和随机本机端口验证：首次设置管理员、重复启动复用同一进程、停止后服务退出、重启保持账号不变、端口占用报错、损坏账号文件不被覆盖、后台进程在启动器退出后继续服务、重复停止、无关进程保护、后台失败报告。结果为 `LAUNCHER CHECKS PASSED`，该自动化测试结束删除自己的临时目录。

Windows `cmd.exe` 已实测中文路径下的后台启动与停止入口：启动命令返回后，从 Windows 请求独立测试端口仍可访问；执行停止入口后服务退出；重复停止正常返回。自动打开浏览器已通过 WSL 调用 Windows 默认 Chrome，并现场确认登录页。未替用户设置正式管理员密码。桌面启停快捷方式的目标与工作目录已核实；统一后的 `make test` 再次通过全部 893 项业务/权限检查。
