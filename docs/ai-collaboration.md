# 本次 AI 协作与改进记录

日期：2026-10-22。工具：OpenAI Codex。

用户要求检查并完善已有 ClubManager，自主选择合适的扩展。assignmentP.md 用作课程交付背景资料，未执行其中的投稿、发布或提交建议。

## 案例 1：已有测试通过，但网页不能正常显示

原版 C++ 测试实际通过 201 条断言。检查发现 `/api/members` JSON 缺少闭合花括号；前端有些位置读 `response.members`，另一些位置读 `response.data`；组织架构路由的路径段数量也不匹配。修复响应与读取后，加入启动真实服务器的 Python 标准库测试，验证成员/活动/组织/审批/导出及错误参数。没有将原来的“全部通过”当成项目已经可用的证据。

## 案例 2：撤销必须恢复业务结果

原取消报名的逆操作只把退出者放回候补，不能撤销已经发生的候补转正；候补报名未记录撤销命令。改为保存活动操作前后的完整状态。入社/退社纳入命令栈；审批内部直接修改成员名单并使用一个命令，避免撤销闭包再次创建新命令。新增测试检查正取、候补、积分和待审队列的准确恢复。

原测试还把“查看下一条申请”当成消费队列，导致未审批项从待审数量消失。改为查看不消费，正式审批/撤回再移除，并同步更新测试预期。容量测试原来保留第一个报名者，与原文档所称的积分优先不一致；改为按当前积分保留，并让已签到成员优先。

## 案例 3：功能扩展要有闭环

选取统计总览、个人日程、签到积分、活动结束、申请撤回和 CSV 导入导出，沿用现有数据模型。新功能同时接入业务接口、CLI/网页、持久化和回归测试。未增加付费服务、数据库或公网部署。

存档由直接清空内存再解析，改为临时对象解析校验，通过后才替换；写入临时文件完成后再替换目标文件。用包含分隔符、换行、标签及逻辑删除实体的样例验证往返；用截断文件、坏数字、错误 ID、非法引用和组织环路验证拒绝行为。

## 案例 4：按用户追加要求接入登录与权限

用户明确要求区分管理员和普通成员，普通成员仅可操作自己的报名、签到和入社申请。将服务端认证集中在统一入口，成员业务使用允许列表与登录账号身份，配合仅本人数据返回；管理员账号管理与普通成员页面分别实现。使用平台密码学库加盐哈希，随机 Cookie 会话、CSRF、登录失败限速以及角色/密码变更时的会话失效。

单凭成员数字 ID 绑定会在导入不同存档后发生身份误关联，因此 v3 存档增加稳定随机绑定标识，账号库独立保存；旧数据仍可加载，但必须核实后重新绑定。新增真实 HTTP 权限测试，直接伪造参数、访问管理路径，验证不能依靠前端隐藏按钮来防越权；另外使用 Python hashlib 对照平台生成的密码哈希。

## 案例 5：保留安全设置，迁移运行环境并减少占用

Windows 智能应用控制阻止新构建 EXE 后，按用户要求转入已有 WSL Ubuntu-24.04。源码仍在原项目目录，构建放入 Linux 文件系统，避免 NTFS 时间戳差异；缺少的 OpenSSL 开发包通过 Ubuntu 软件源校验后解包到项目私有目录，无需 sudo，不修改系统包或安全策略。WSL 实际通过 893 项检查，浏览器验证了登录、成员本人操作和管理员账号页。

按用户要求减少空间占用，清理了 341.5 MiB 一次性下载索引、软件包、旧 Windows 程序和重复构建。保留一套约 3.9 MiB Linux 构建与约 8.1 MiB 必要依赖；脚本以后自动清理下载缓存，账号和有效业务数据不进入清理范围。
